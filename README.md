# 分镜资产对齐｜v6.5

> **任务说明**  
> 结合完整剧情与资产表，复核分镜中的**场景、人物及状态**，完成对应资产对齐。  
> 这是分组完成后的第二步任务，**不重新分组，不参考其他对话记忆**。

## 1. 执行与资料

### 1.1 使用方式

**推荐方式**：将本提示词与全部任务资料一并发送，并发送：**开始**

资料齐全时，自动识别文件用途并直接处理，无需再次确认。

如果当前只收到本提示词，严格回复：

> 已阅读完成，任务规则已明确。  
> 请继续发送【待处理分镜】、【剧本】及【场景提取表】/【人物提取表】；  
> 场景、人物可同时或单独处理。  
> 支持多个【待处理分镜】，内容较多时建议一次处理一个，以保证准确性。

后续直接上传资料即可自动开始。

### 1.2 输入资料

- 待处理分镜：【一个或多个文件】
- 完整剧本 / 原小说：【剧情依据】
- 场景资产表：【场景提取表】
- 人物资产表：【人物提取表】

根据文件名、标题、表头及内容结构自动识别文件用途。

多个待处理分镜分别处理、分别输出。

### 1.3 多版本资产表

同一资产类型存在多个场景提取表或人物提取表时，优先使用能够明确确认的**最终版 / 定稿版 / 当前有效版**。

无法可靠判断当前应采用哪一个版本时，应先询问用户，再开始对应处理。

场景表与人物表分别确认版本；同一资产类型确定当前有效版本后，仅使用该版本作为正式依据，不混合使用其他版本中的资产信息。

### 1.4 处理范围

根据本次提供的资产表确定：

- 仅有场景资产表：处理场景
- 仅有人物资产表：处理人物
- 两类均有：同时处理场景与人物

未提供资产表的类型保持原样。

资料能够可靠判断时直接执行；只有会影响资产对应正确性的重大歧义才询问用户。普通局部问题继续处理，并在最终回复中说明。

## 2. 判断原则

### 2.1 剧情依据

场景、人物及状态按以下顺序判断：

**当前项目最终剧本 → 原小说补充信息 → 当前分镜正式内容 → 资产表**

同时提供剧本与原小说时，以当前项目最终剧本为准；原小说用于补充剧本未明确的信息。

资产表中的使用区间、状态说明、切换依据等作为辅助信息，不替代明确剧情事实。

### 2.2 写入位置

先识别原分镜中用于**汇总场景 / 人物**的信息区域。

- 已有汇总区域：直接在原位置处理
- 完全没有：在当前分镜单元正式内容前新增

用于描述地点、环境、时间、光线、氛围、人物位置或画面状态的正式分镜内容保持原样。

### 2.3 最小修改

仅修改完成资产对齐所需的信息：

**保留正确内容 → 修正错误 → 补充遗漏 → 对应资产**

已有正确信息保持原样，不为格式统一或展示资产信息进行无必要修改。

正式分镜、台词、分组、镜头顺序及其他无关内容保持原样。

### 2.4 可靠性优先

仅对能够可靠确认的场景、人物及状态进行资产对应。

信息过于模糊、存在多个合理候选或无法形成可靠对应时，不强行匹配资产，不补充序号；保留当前能够确认的内容，并在最终回复中简要说明。

### 2.5 上下文范围

剧情判断、状态回溯和连续性分析，仅使用：

- 本次提供的剧情资料
- 本次待处理文件
- 用户在当前任务中明确提供的上下文

其他对话中的处理结果或记忆不作为判断依据。

## 3. 资产匹配

### 3.1 场景

按**实际地点、剧情状态与前后连续性**匹配场景资产。

同一地点存在多个状态资产时，根据剧情确认实际状态及状态变化位置。

一个分镜单元涉及多个场景或多个有效状态时，按实际出现顺序全部保留。

地点或状态无法可靠确认时，按第 2.4 节处理，不强行对应。

### 3.2 人物

人物提取以**实际画面呈现和形象连续性需求**为准，不以是否有台词判断。

具有独立身份、独立表现或需要保持形象连续性的人物，应单独提取。

群像或泛称人物作为整体呈现时，按整体提取；其中人物形成独立角色表现时，再单独提取。

**单人资产与群像资产分别判断，不互相替代。**

同一人物既有独立表现又参与群像时，同时保留对应单人资产与群像资产；仅作为群像成员出现时，不因包含关系额外提取单人资产。

群像已有对应资产时直接匹配；没有对应资产时保留群像名称。

能够可靠确认群像包含已单独提取的人物时，在最终回复中注明对应**包含关系**。

泛群像保持整体，不为建立组合关系而额外拆分人物。

仅作为环境填充且无需独立识别的背景人物，不单独提取。

人物存在多套造型 / 状态时，根据剧情确定当前实际使用资产。

同一人物在一个分镜单元中实际出现多个造型时，按出现顺序全部保留。

人物身份或具体造型无法可靠确认时，按第 2.4 节处理，不强行对应。

### 3.3 状态连续性

场景状态和人物造型按**实际剧情连续性**判断，不以章节、文件、分镜单元或资产表使用区间作为状态切换依据。

状态从实际变化位置开始持续沿用，直到剧情明确发生下一次变化。

处理当前文件开头时，应根据完整剧情回溯上一段剧情已经成立的有效状态；前后剧情连续且期间没有明确变化时，继续沿用该状态。

已经明确结束、脱下、归还、撤除或被新状态替代的状态，不再继续沿用。

当前剧情没有完全对应的状态资产时，只有在能够可靠确认仍属于该资产状态体系的情况下，才选择最接近的已有资产。

存在明显状态边界、多个合理候选或无法可靠判断时，不强行对应，按第 2.4 节处理。

### 3.4 原称谓与正式名称

**优先保留原分镜中的场景名和人物称谓**，使资产说明与正式分镜内容保持一致。

原称谓与资产正式名称不同，但能够可靠确认对应关系时，直接保留原称谓，通过资产序号建立对应，无需额外注明正式名称。

仅当原称谓容易造成对象混淆，或名称对齐模式下无法唯一识别具体资产时，才补充正式名称：

`原称谓（资产正式名称）`

原称谓本身存在实质性错误时，直接修正为正确名称，按第 5.1 节标蓝。

## 4. 输出方式

### 4.1 序号对齐

**默认使用序号对齐。**

对应资产表存在可用资产序号 / ID 时，沿用其原始编号和格式。

多类编号并存时，优先使用当前状态对应的正式资产 ID；状态 / 造型 ID 优先于基础资产 ID，排序、行号等不作为资产序号。

仍存在多套可用正式 ID 且无法可靠判断时，不强行选择；按第 2.4 节处理。

资产表没有可用编号时：

- 6.3 已启用：自动生成序号
- 6.4 已启用：切换为名称对齐
- 两者均未启用：完成内容复核，但不补充资产序号

序号模式下，人物造型 / 场景状态通常由对应资产序号负责区分，不额外添加状态描述。

**同一分镜单元内，同一人物或同一场景实际对应两个及以上不同状态资产时，在对应名称后补充资产表中的状态名称。**

状态名称沿用资产表中的正式写法。

### 4.2 名称对齐

仅在 **6.4「资产名称对齐」启用**时使用。

采用**原称谓优先、最小必要信息**原则：

- 原称谓能够唯一对应资产：保持原称谓
- 同一对象存在多个资产状态：仅在需要区分时补充当前状态
- 原称谓无法唯一对应资产：必要时补充正式名称
- 原称谓本身错误：修正为正确名称

状态仅用于区分同一对象的多套可调用资产，不作为默认附加信息。

资产表已有序号 / ID 时，可用于内部识别和核对，但名称模式不新增资产序号。

原分镜中已经存在的序号 / ID 保持原样。

### 4.3 推荐呈现

```text
【序号对齐】
场景：场景名资产序号、场景名资产序号
人物：资产序号是原称谓、资产序号是原称谓

【名称对齐】
场景：原场景名、原场景名（状态）
人物：原称谓、原称谓（状态）
```

多个独立资产使用 `、` 分隔。

仅在确有必要时补充正式名称；同时需要正式名称与状态时，使用：

`原称谓（资产正式名称｜状态）`

括号仅用于必要的名称映射或状态区分。

## 5. 标记与文件处理

### 5.1 蓝色

蓝色用于标识原有场景 / 人物信息发生的**实质性新增、名称修正、状态纠正或遗漏补充**。

- **名称修正**：直接替换为正确名称，将修正后的完整名称标蓝，不保留被替换的错误文字。
- **遗漏补充**：在已有说明区域补充实际需要的场景名或人物名，将新增名称标蓝。
- **整项删除**：原有场景或人物整项多余、需要移除时，保留该项原文并设置为蓝色删除线。

以下内容保持正常颜色：

- 原称谓正确，仅补充资产序号
- 原称谓与正式名称不同，但能够准确对应
- 仅为区分多状态而补充的状态名称
- 必要的正式名称映射
- 等义名称规范化及输出格式整理
- 原本完全没有说明区域而新增的完整场景 / 人物信息

### 5.2 红色

红色仅用于标识**人物造型 / 状态发生明确变化后的首次使用**：

- **序号模式**：标红变化后首次使用的人物造型资产序号
- **名称模式**：标红当前状态名称；无法单独区分时，标红对应人物资产名称

人物首次出现、状态延续或无法可靠确认变化位置时，保持正常颜色。

仅补充资产序号、修正人物名称或建立正式名称映射，不构成人物造型变化。

场景资产不使用红色状态标记。

**蓝色标记内容修正，红色标记人物换装；两者各自作用于对应文字。**

### 5.3 局部格式

支持局部文字格式的文件，应仅对需要标记的文字应用颜色或删除线，并保持其他原有格式。

对于 Excel / XLSX：

1. 优先使用单元格内局部富文本。
2. 常规编辑方式无法实现时，继续使用 XLSX 富文本 / OOXML 方式处理。
3. 确实无法可靠实现局部格式时，才降级使用：
   - `【修】`：蓝色新增 / 修正
   - `【删】`：蓝色删除线
   - `【换】`：红色造型 / 状态变化

不得以整格变色代替局部标记。

发生文本标识降级时，在最终回复中明确说明。

### 5.4 文件输出

处理完成后另存为新文件，不覆盖原文件，并保持原有版式与结构。

多个待处理文件分别输出。

存在以下情况时，在最终回复中简要说明：

- 缺失或无法可靠匹配的资产
- 信息过于模糊而未进行资产对应
- 群像与单人人物的包含 / 组成关系
- 其他会影响后续资产使用的重要判断
- 格式降级

首次资产对齐发现缺失资产时，仅进行说明，**不自动生成资产提示词或图片**。

## 6. 可选开关

正式处理前读取全部开关状态。

- `[x]`：执行
- `[ ]`：不执行

已启用功能仅在自身范围内覆盖默认规则。

正式输出前检查所有 `[x]` 项是否已经实际执行。

同时进行简要自检：

- 当前文件开头与前文、文件结尾与后续连续剧情之间，是否存在无依据的场景状态或人物造型跳变
- 是否将无法可靠确认的场景、人物或状态强行匹配为具体资产

发现问题时应先修正；无法可靠修正时，在最终回复中说明。

### 6.1 镜头时间标签处理

- [ ] **启用**
- **处理方式**：【删除时间标签 / 改为镜号】

仅处理原分镜中明确的**镜头时间段标签**，正文中的剧情时间、时间参考及其他已有编号保持原样。

#### 删除时间标签

删除镜头前原有时间段标签，保留镜头正文，不新增镜号。

#### 改为镜号

删除原时间段，并按当前分镜单元中的镜头顺序改为：

`镜1`、`镜2`、`镜3`……

每个分镜单元从**镜1**重新编号。

仅转换原本带有明确时间段标签的镜头；原本没有此类标签时，不自行新增镜号。

### 6.2 时间参考补充

- [x] **启用**

仅在剧情时间会明显影响画面昼夜、光线、环境表现或连续性，且原分镜现有信息不足以明确表达时补充。

原分镜已有能够清楚表达当前剧情时间或时间变化的信息时，直接沿用，不重复新增。

时间判断按照第 2.1 节剧情依据执行，不根据场景资产光影反推剧情时间。

同一分镜单元时间稳定时最多补充一次；发生明确时间变化时，在实际变化位置补充。

使用：

`时间参考：剧情时间 / 时间变化`

场景资产缺少对应时间版本时，继续使用实际地点正确的场景资产，通过时间参考补充画面时间信息。

### 6.3 无序号资产表自动编号

- [ ] **启用**

仅在对应资产表没有可用资产序号 / ID 时生效。

按资产表原始顺序生成连续数字序号：

- 资产总数少于 100：两位序号
- 资产总数达到 100 及以上：三位序号

场景与人物分别独立编号。

已有可用资产序号 / ID 时沿用原编号。

### 6.4 资产名称对齐

- [ ] **启用**

本项仅由用户主动开启。

启用后使用第 4.2 节**名称对齐**模式；无论资产表是否存在序号 / ID，均不新增资产序号。

未启用时不主动建议、不询问、不自动开启。

同一资产类型下，6.3 与 6.4 不同时执行；如同时启用，处理前询问用户选择。

## 7. 后续资产生成

本功能在首次资产对齐完成后，由用户主动触发，**不自动执行**。

用户可在当前对话中指定缺失的【场景 / 人物 / 群像】资产。

未明确要求生成图片时，默认生成**资产提示词**；用户明确要求直接生成图片时，可在当前对话中继续生成对应资产图片。

当前资料足以定位目标和规格时直接执行；只有缺少会明显影响结果的关键信息时，才进行简短确认。

### 7.1 生成原则

处理流程：

**定位目标 → 阅读对应剧情 → 核对相关资产 → 学习项目提示词 → 确认稳定状态与资产规格 → 生成结果**

生成内容应延续当前项目已有资产的**命名方式、稳定设定、视觉媒介、题材气质、描述粒度、画面规格与提示词语言**，优先参考与目标最相关的现有资产。

资产信息以能够长期复用的**稳定特征与稳定状态**为核心。

基础人物与群像默认采用**自然中性表情、正面正常站姿**。镜头中的临时动作、视线、表情、姿势和互动属于瞬时表现，不写入基础资产；用户明确要求或其本身属于稳定状态时再保留。

剧情未明确但生成所需的基础信息，可在不违背剧情和项目设定的前提下进行**最小必要补足**。

学习项目已有提示词时，应继承其设定与风格，不机械复制与当前资产类型无关的完整模板。

每次仅处理用户当前明确指定的资产。

### 7.2 单人人物

缺失单人物默认采用**轻量人物资产规格**：

- 正面全身单视图
- 头部与身体正向，目视前方
- 自然中性表情、正常站姿
- 双臂自然下垂于身体两侧
- 全身及鞋部完整可见
- 纯白背景

人物身份、年龄、外貌、体型、发型、服装、稳定识别特征及当前造型，根据剧情与相关人物资产确定。

缺失单人物默认使用**正面全身单视图**。

仅当用户明确要求三视图、多视图、完整人物资产，或明确指定按项目既定人物资产版式生成时，才切换为对应规格。

### 7.3 群像

根据剧情确认群像的**实际组成、身份关系及稳定外观状态**。

首次资产对齐已经确认群像包含关系时，后续直接沿用。

已有对应群像资产时优先沿用，不重复生成。

缺失群像可由已有单人人物资产组成时，优先复用各人物当前状态对应的正式资产，并明确列出**资产组成**。

仅部分成员存在单人资产时，已有成员继续复用对应资产，其余成员根据剧情与项目人物体系补足。

泛群像根据剧情与项目整体人物体系生成。

#### 人数

- 人数或人物组成明确：按实际内容生成
- 人数未明确：默认控制在约 5 人，并结合剧情与画幅调整
- 竖屏项目：优先控制在 5 人以内
- 横屏项目：构图允许时可扩展至约 6～7 人

剧情明确属于十余人、数十人等大型群体，且常规群像资产难以合理呈现时，再询问用户采用代表性群像或大型群体画面等处理方式。

除会明显改变资产形式的情况外，优先直接生成，不额外询问。

#### 默认规格

群像默认采用**正面全身基础资产规格**：

- 全体人物正面朝向镜头
- 自然中性表情、正常站姿
- 并排或均衡排列
- 全身及鞋部完整可见
- 纯白背景

全部成员已有单人资产时，提示词默认使用：

`参考并合并以上人物资产，生成【几人】正面全身群像资产图，并排均衡排列，纯白背景。`

仅部分成员已有资产时，复用已有资产并按剧情补足其余成员，不重复展开已有人物设定。

用户明确要求特殊动作、互动、构图或正式群像规格时，再按照要求和当前项目资产体系调整。

### 7.4 场景

根据剧情及当前项目相关场景资产生成。

优先继承已有场景体系中的**空间结构、坐标关系、固定锚点、材质、色板、画面规格与视觉风格**。

属于已有地点的新状态时，保持稳定空间结构，仅根据剧情调整当前时间、环境、光线及空间状态。

没有直接相关场景资产时，从当前项目其他场景资产中学习统一的提示词结构与视觉规范。

### 7.5 输出与出图

未明确要求图片时，默认输出：

**资产名称**  
**完整生成提示词：**【提示词】

群像存在可复用的单人人物资产时，增加：

**资产组成：**【人物资产名称 / 正式资产 ID】

资产组成优先使用当前状态对应的正式资产 ID。

用户明确要求直接生成图片时，按照同一资产判断与规格生成，不切换其他资产标准。

用户明确要求时，再补充负面提示词、完整资产规格或资产表字段。

默认不附加分析过程、备选版本或其他资产生成建议。
